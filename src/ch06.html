الگوهای حرفه‌ای Zustand — TypeScript و اسلایس‌ها

از این فصل به بعد مثل یک تیم واقعی کد می‌زنیم: استورهای تایپ‌دار با TypeScript، الگوی اسلایس برای استورهای بزرگ، subscribe با سلکتور و ملاحظات SSR.

در این فصل یاد می‌گیرید

  • فرم کِرید (curried) تایپ‌دار create<State>()(...)
  • الگوی Slices برای شکستن استورهای بزرگ
  • subscribeWithSelector و کاربردهای عملی
  • ساختار پوشه‌بندی استور در پروژه‌های واقعی و نکات SSR

TypeScript با Zustand

در Zustand نسخهٔ ۵، فرم استاندارد نوشتن استور تایپ‌دار «کِرید» است — یعنی دو بار پرانتز. دلیلش این است که TypeScript برای اینکه هم State و هم اکشن‌ها را درست حدس بزند، باید تایپ را «قبل از» دیدن تابع شما بداند:

src/store/useCounterStore.tsts
import { create } from 'zustand'

// ۱) تایپ کل State: داده + اکشن‌ها
type CounterState = {
  count: number
  increment: (by?: number) => void
  decrement: (by?: number) => void
  reset: () => void
}

// ۲) create<CounterState>()  ← پرانتز اول؛ بعد تابع
export const useCounterStore = create<CounterState>()((set) => ({
  count: 0,
  increment: (by = 1) => set((s) => ({ count: s.count + by })),
  decrement: (by = 1) => set((s) => ({ count: s.count - by })),
  reset: () => set({ count: 0 }),
}))

از این لحظه اگر increment(2) را با آرگومان رشته صدا بزنید یا فیلدی را تایپ اشتباه بخوانید، کامپایلر خطا می‌دهد — همان چیزی که در تیم‌ها جان شما را نجات می‌دهد.

هشدار — پرانتز جا نماند!

فرم اشتباه: create<CounterState>((set) => ...) (بدون پرانتز وسط). در این شکل استنتاج تایپ اکشن‌ها درست کار نمی‌کند و در مکان‌های استفاده خطای عجیب می‌گیرید. یادتان باشد: create<State>() سپس ((set) => ...).

تایپ‌های کمکی برای persist

وقتی میان‌افزار هم هست، زنجیرهٔ تایپ به ترکیب میان‌افزارها وابسته است؛ برای همین به‌جای نوشتن همه‌چیز دستی، از همان فرم کِرید استفاده می‌کنیم و اگر لازم شد، تایپ State را با Partialize محدود می‌کنیم:

persist تایپ‌دارts
import { create } from 'zustand'
import { persist } from 'zustand/middleware'

type CartState = {
  items: { id: number; qty: number }[]
  addItem: (id: number) => void
}

export const useCartStore = create<CartState>()(
  persist(
    (set) => ({
      items: [],
      addItem: (id) =>
        set((s) => ({ items: [...s.items, { id, qty: 1 }] })),
    }),
    {
      name: 'cart',
      // فقط items ذخیره شود؛ تایپ همین را تحمیل می‌کند
      partialize: (s) => ({ items: s.items }),
    }
  )
)

الگوی Slices: استور بزرگ را بشکنید

اگر همهٔ اپ را در یک استور بریزید (کاربر، سبد، فیلترها، نوتیفیکیشن...)، فایل صدها خط می‌شود و هر تغییر، rebase دردناک می‌سازد. الگوی Slices راه‌حل رسمی Zustand است: هر دامنه یک «اسلایس» مستقل، و ترکیب آن‌ها در یک استور واحد. با یک تایپ کمکی شروع می‌کنیم:

src/store/createStore.ts — تایپ کمکیts
import { StateCreator } from 'zustand'

// اسلایس‌ها به هم اشاره می‌کنند؛ یک نوع مشترک برای «کل استور» تعریف می‌کنیم
export type BoundStore = CartSlice & UISlice

export type SliceCreator<T> = StateCreator<
  BoundStore,   // استور نهایی (برای get دیدن همه‌چیز)
  [],           // میان‌افزارهای سفارشی
  [],           // میان‌افزارهای ماقبل
  T             // تایپ همین اسلایس
>
src/store/slices/cartSlice.tsts
import { SliceCreator } from '../createStore'

export type CartSlice = {
  items: { id: number; qty: number }[]
  addItem: (id: number) => void
  removeItem: (id: number) => void
  clear: () => void
}

export const createCartSlice: SliceCreator<CartSlice> = (set, get) => ({
  items: [],
  addItem: (id) =>
    set((s) => {
      const found = s.items.find((i) => i.id === id)
      if (found) {
        return { items: s.items.map((i) => (i.id === id ? { ...i, qty: i.qty + 1 } : i)) }
      }
      return { items: [...s.items, { id, qty: 1 }] }
    }),
  removeItem: (id) => set((s) => ({ items: s.items.filter((i) => i.id !== id) })),
  clear: () => set({ items: [] }),
})
src/store/slices/uiSlice.tsts
import { SliceCreator } from '../createStore'

export type UISlice = {
  cartOpen: boolean
  toggleCart: (open?: boolean) => void
}

export const createUISlice: SliceCreator<UISlice> = (set) => ({
  cartOpen: false,
  toggleCart: (open) => set((s) => ({ cartOpen: open ?? !s.cartOpen })),
})
src/store/useBoundStore.ts — ترکیب نهاییts
import { create } from 'zustand'
import { createCartSlice } from './slices/cartSlice'
import { createUISlice } from './slices/uiSlice'
import { BoundStore } from './createStore'

export const useBoundStore = create<BoundStore>()((...a) => ({
  ...createCartSlice(...a),
  ...createUISlice(...a),
}))

حالا یک استور واحد دارید که هر اسلایس فایل خودش را دارد؛ و پاداش بزرگ: اسلایس‌ها به State همدیگر هم دسترسی دارند (از طریق get). مثلاً addItem می‌تواند بعد از افزودن، toggleCart(true) صدا بزند.

نکته — یک استور بزرگ یا چند استور کوچک؟

هر دو الگو قابل قبول است. اگر بخش‌ها مستقل‌اند (تم و سبد هیچ ربطی به هم ندارند) چند استور جدا بسازید. اگر باید با هم تعامل کنند یا منطق مشترک دارند، اسلایس. آنچه ممنوع است، «استور خدای ۱۵۰۰ خطی» است.

subscribeWithSelector: گوش دادن هدفمند

subscribe پیش‌فرض به هر تغییر گوش می‌دهد. میان‌افزار subscribeWithSelector نسخهٔ سلکتوردار می‌دهد — مثل useEffect اما بدون رندر:

subscribe به یک فیلد خاصts
import { subscribeWithSelector } from 'zustand/middleware'

const useBoundStore = create<BoundStore>()(
  subscribeWithSelector((...a) => ({ /* اسلایس‌ها */ }))
)

// هر جا (مثلاً App):
useEffect(() => {
  const unsub = useBoundStore.subscribe(
    (s) => s.items.length,               // فقط این مقدار مهم است
    (len, prevLen) => {                  // فقط وقتی عوض شود صدا می‌شود
      if (len > prevLen) toast('به سبد اضافه شد!')
    },
    { equalityFn: Object.is }            // اختیاری
  )
  return unsub
}, [])

کاربردهای واقعی: نمایش toast بعد از افزودن به سبد، ذخیرهٔ خودکار draft بعد از تغییر متن، گزارش analytics روی اکشن‌های خاص.

ساختار پروژه و نکات SSR در یک نگاه

قرارداد پوشه‌بندی حرفه‌ایtext
src/
├── store/
│   ├── useBoundStore.ts      # ترکیب اسلایس‌ها (اگر الگوی اسلایس)
│   ├── slices/
│   │   ├── cartSlice.ts
│   │   └── uiSlice.ts
│   └── useAuthStore.ts       # استورهای مستقل دامنه‌ای
├── features/                 # کامپوننت‌ها کنار دامنهٔ خودشان
│   ├── cart/
│   └── products/
└── lib/                      # کد عمومی (api، utils)
  • SSR / Next.js: localStorage روی سرور وجود ندارد. اگر persist دارید، آپشن skipHydration: true بدهید و بعداً در سمت کلاینت با useCartStore.persist.rehydrate() ادامه دهید. در SPA معمولی این موضوع ندارید.
  • Testability: چون استور شیء معمولی است، در تست‌ها با useXStore.setState({...}) مستقیم سناریو می‌سازید — فصل ۱۴ کاملش می‌کند.
  • قانون تنهایی: استور نباید fetch بلد باشد مگر برای فرمان‌های دستورالعملی؛ خواندن دادهٔ سرور کار Query است (فصل بعدی).

جمع‌بندی فصل

  • TS با فرم کِرید: create<State>()((set) => ...) — پرانتز دوم را فراموش نکنید.
  • الگوی اسلایس = هر دامنه یک فایل + تایپ مشترک + ترکیب در یک استور.
  • subscribeWithSelector گوش دادن بدون رندر به یک فیلد خاص می‌دهد.
  • در SSR با persist از skipHydration استفاده کنید؛ در SPA نیازی نیست.
  • چند استور مستقل برای دامنه‌های بی‌ربط؛ اسلایس برای دامنه‌های متعامل.
