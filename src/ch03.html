عمق Zustand — set، get و کار با استور از هر جا

قدرت واقعی Zustand وقتی آشکار می‌شود که بفهمید استور فقط یک شیء زندهٔ خارج از React است: از اکشن‌های async تا خواندن و نوشتن State داخل توابع معمولی جاوااسکریپت.

در این فصل یاد می‌گیرید

  • پارامتر get در اکشن‌ها و حالت replace در set
  • نوشتن اکشن‌های async با الگوی loading/error
  • API کامل استور: getState، setState، subscribe — بیرون از React
  • الگوی reset و استخراج State اولیه

پارامتر get: خواندن آخرین نسخهٔ State داخل اکشن

تا حالا همهٔ اکشن‌ها فقط set را دیسکت می‌کردند. اما create دو پارامتر به شما می‌دهد: (set, get). get همان لحظه، آخرین نسخهٔ State را برمی‌گرداند:

src/store/useWishlistStore.jsjs
import { create } from 'zustand'

export const useWishlistStore = create((set, get) => ({
  items: [],

  // toggle با get: اول بخوان، بعد تصمیم بگیر
  toggle: (product) => {
    const exists = get().items.some((i) => i.id === product.id)
    if (exists) {
      set({ items: get().items.filter((i) => i.id !== product.id) })
    } else {
      set({ items: [...get().items, product] })
    }
  },

  clear: () => set({ items: [] }),
}))

همین کار را می‌شد داخل set((state) => ...) هم کرد؛ تفاوت ظریف اینجاست: اگر اکشن چند set پشت‌سرهم داشته باشد، get() همیشه نسخهٔ تازه را می‌دهد اما پارامتر state داخل یک set فقط نسخهٔ همان لحظه است. در اکشن‌های چندمرحله‌ای (مخصوصاً async) get انتخاب مطمئن‌تری است.

حالت کم‌کاربرد اما مهم: replace

set یک آرگومان دوم دارد. اگر true بدهید، به‌جای merge، کل State را جایگزین می‌کند:

replace — کل State عوض می‌شودjs
set({ items: [] }, true) // اکشن‌ها هم حذف می‌شوند! تقریباً هرگز این کار را نکنید

هشدار

set(obj, true) کل استور (از جمله اکشن‌ها) را با آن شیء عوض می‌کند. اگر اکشن‌ها را در شیء جدید نیاورده باشید، عملاً استور را می‌سوزانید. ۹۹٪ موارد باید replace نزنید.

اکشن‌های async: بارگذاری داده با loading و error

اکشن‌ها توابع معمولی هستند؛ پس می‌توانند async باشند. الگوی استاندارد برای فراخوانی API داخل استور:

src/store/useNotificationsStore.jsjs
import { create } from 'zustand'

export const useNotificationsStore = create((set, get) => ({
  items: [],
  status: 'idle', // idle | loading | success | error
  error: null,

  fetchAll: async () => {
    if (get().status === 'loading') return // جلوگیری از درخواست موازی
    set({ status: 'loading', error: null })
    try {
      const res = await fetch('/api/notifications')
      if (!res.ok) throw new Error(`HTTP ${res.status}`)
      const items = await res.json()
      set({ items, status: 'success' })
    } catch (err) {
      set({ status: 'error', error: err.message })
    }
  },

  markAllRead: async () => {
    const ids = get().items.filter((n) => !n.read).map((n) => n.id)
    await fetch('/api/notifications/read', {
      method: 'POST',
      body: JSON.stringify({ ids }),
    })
    set((s) => ({
      items: s.items.map((n) => ({ ...n, read: true })),
    }))
  },
}))
src/Notifications.jsxjsx
import { useEffect } from 'react'
import { useNotificationsStore } from './store/useNotificationsStore'

export default function Notifications() {
  const items = useNotificationsStore((s) => s.items)
  const status = useNotificationsStore((s) => s.status)
  const fetchAll = useNotificationsStore((s) => s.fetchAll)

  useEffect(() => {
    fetchAll()
  }, [fetchAll])

  if (status === 'loading') return <p>در حال بارگذاری...</p>
  if (status === 'error') return <p>خطا در دریافت اعلان‌ها</p>
  return <ul>{items.map((n) => <li key={n.id}>{n.text}</li>)}</ul>
}
هشدار — این کد را در پروژهٔ واقعی برای دادهٔ سرور ننویسید!

الگوی بالا برای «فراخوانی‌های دستورالعملی» (مثلاً ثبت لاگ، ارسال فرم به API خارج از کش) مناسب است، اما برای داده‌ای که از سرور می‌خوانید و در UI نشان می‌دهید، نوشتن دستی loading/error/caching یعنی بازاختراع TanStack Query به شکل شکسته. از فصل ۸ به بعد، خواندن داده فقط با Query انجام می‌شود و این الگو را در جای درستش می‌بینیم.

استور، فراتر از کامپوننت: getState و setState

هوکی که create برمی‌گرداند، خودش چند متد اضافه دارد که استور را از «دنیای بیرون React» قابل استفاده می‌کند:

متدکاررندر می‌کند؟
useXStore.getState()خواندن لحظه‌ای State (بدون subscribe)خیر
useXStore.setState(partial)نوشتن مستقیم State از بیرون اکشن‌هابله (برای مشترکین)
useXStore.subscribe(fn)گوش دادن به هر تغییر (بازگشت unsubscribe)خیر
useXStore.destroy()پاک‌سازی استور (به‌ندرت، در تست‌ها)—

کاربردهای واقعی‌ای که در پروژه‌های شرکت‌ها هر روز می‌بینید:

src/lib/api.js — اتصال استور به لایهٔ شبکهjs
import { useAuthStore } from '../store/useAuthStore'

// ۱) خواندن توکن در interceptor — جایی که هوک نداریم!
api.interceptors.request.use((config) => {
  const token = useAuthStore.getState().token
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})

api.interceptors.response.use(
  (res) => res,
  (err) => {
    // ۲) نوشتن مستقیم از بیرون: 401 یعنی نشست منقضی شده
    if (err.response?.status === 401) {
      useAuthStore.getState().logout()
    }
    return Promise.reject(err)
  }
)

نکته

« getState در event handler» یکی از رایج‌ترین الگوهای بهینه‌سازی است: وقتی در onClick به مقدار فعلی نیاز دارید ولی نمی‌خواهید تغییراتش باعث رندر شود، به‌جای subscribe به آن در کامپوننت، همان لحظه getState() بخوانید. (کاملش در فصل ۴ زیر عنوان «Transient Updates».)

الگوی reset: استخراج State اولیه

با رشد استور، «ریست به اول» سخت می‌شود. راه استاندارد، بیرون کشیدن State اولیه در یک ثابت است:

src/store/useFiltersStore.jsjs
import { create } from 'zustand'

const initialState = {
  query: '',
  category: 'all',
  minPrice: 0,
  sort: 'newest',
}

export const useFiltersStore = create((set) => ({
  ...initialState,
  setQuery: (query) => set({ query }),
  setCategory: (category) => set({ category }),
  setSort: (sort) => set({ sort }),
  reset: () => set({ ...initialState }), // شیء تازه؛ نه replace
}))

دو نکته: اول اینکه reset با merge ساده انجام شد (بدون true)، چون اکشن‌ها جزء State هستند و باید بمانند. دوم اینکه استور فیلترها نمونهٔ خوبی از مرز Client State و URL State است — در پروژهٔ فصل ۱۳ بحثش می‌کنیم.

جمع‌بندی فصل

  • get() آخرین نسخهٔ State را داخل اکشن می‌دهد؛ برای اکشن‌های چندمرحله‌ای و async.
  • set(partial, true) کل State را جایگزین می‌کند — تقریباً هرگز لازم نیست.
  • اکشن async با الگوی idle → loading → success/error نوشته می‌شود؛ اما برای «دادهٔ سرور» جای این الگو TanStack Query است.
  • getState/setState/subscribe استور را به لایه‌های غیر React (interceptor، روتر، توابع کمکی) وصل می‌کنند.
  • ریست استاندارد = استخراج initialState + اکشن reset با merge ساده.
تمرین فصل ۳

استور useAuthStore بسازید با فیلدهای token و user و اکشن‌های login(email, password) (async با delay ساختگی ۵۰۰ میلی‌ثانیه و الگوی loading)، logout و reset. بعد یک تابع api ساختگی بنویسید که با getState() توکن را بخواند و اگر توکن نبود، Promise reject کند. خروجی را در کنسول با subscribe دنبال کنید و ببینید هر اکشن چه تغییری می‌سازد.
