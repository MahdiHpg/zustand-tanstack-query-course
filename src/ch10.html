useMutation — تغییر داده و به‌روزرسانی کش

ساخت، حذف و ویرایش روی سرور؛ چرخهٔ mutation، اینولیدیشن به‌عنوان راهبرد اصلی sync، و به‌روزرسانی خوش‌بینانه با rollback — الگویی که در مصاحبه‌ها پرسیده می‌شود.

در این فصل یاد می‌گیرید

  • تعریف useMutation با mutationFn و فراخوانی با variables
  • چرخهٔ onMutate → onSuccess / onError → onSettled
  • الگوی به‌روزرسانی خوش‌بینانه کامل با snapshot و rollback
  • انتخاب بین invalidation و setQueryData

آناتومی یک mutation

بر خلاف useQuery که هنگام mount خودش اجرا می‌شود، mutation دستی اجرا می‌شود — وقتی کاربر دکمه را زد:

src/lib/api.js — اضافه شدن writeهاjs
async function sendJSON(path, method, body) {
  const res = await fetch(BASE + path, {
    method,
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  })
  if (!res.ok) throw new Error(`API error ${res.status}`)
  return res.json()
}

export const api = {
  // ...پایین همان getهای فصل ۹
  addPost: (post) => sendJSON('/posts', 'POST', post),
  updatePost: (id, patch) => sendJSON(`/posts/${id}`, 'PATCH', patch),
  deletePost: (id) => sendJSON(`/posts/${id}`, 'DELETE').then(() => true),
}
src/components/NewPostForm.jsxjsx
import { useState } from 'react'
import { useMutation, useQueryClient } from '@tanstack/react-query'
import { api } from '../lib/api'

export default function NewPostForm() {
  const [title, setTitle] = useState('')
  const queryClient = useQueryClient()

  const addPost = useMutation({
    mutationFn: (variables) => api.addPost(variables),
    onSuccess: (data, variables) => {
      // ۱) لیست پست‌ها را stale کن تا از سرور تازه شود
      queryClient.invalidateQueries({ queryKey: ['posts'] })
      setTitle('')
    },
    onError: (error, variables) => {
      alert('ذخیره نشد: ' + error.message)
    },
  })

  return (
    <form
      onSubmit={(e) => {
        e.preventDefault()
        addPost.mutate({ title, body: '...', userId: 1 })
      }}
    >
      <input value={title} onChange={(e) => setTitle(e.target.value)} />
      <button disabled={addPost.isPending}>
        {addPost.isPending ? 'در حال ذخیره...' : 'انتشار'}
      </button>
      {addPost.isError && <p className="err">{addPost.error.message}</p>}
    </form>
  )
}
قطعهنقش
mutationFnتنها آرگومان اجباری؛ Promise که سرور را تغییر می‌دهد.
mutate(variables)اجرای mutation؛ هر داده‌ای (فرم، id، فایل) به‌عنوان variables به mutationFn و کالبک‌ها می‌رسد.
isPending / isError / error / dataوضعیت‌ها مثل useQuery — isPending یعنی درخواست در جریان است.
useQueryClient()دسترسی به client برای invalidate و setQueryData بعد از تغییر.
هشدار — mutate یا mutateAsync؟

mutate() هیچ Promiseای برنمی‌گرداند و خطاها را به onError می‌سپارد — انتخاب پیش‌فرض. اگر منطق بعد از اتمام را «آوانس‌محور» می‌خواهید (مثلاً navigate بعد از موفقیت)، از const res = await mutateAsync(vars) داخل try/catch استفاده کنید. هرگز mutateAsync را بدون try/catch صدا نزنید؛ unhandled rejection می‌گیرید.

چرخهٔ کامل کالبک‌ها

onMutateقبل از درخواست — جای optimistic update
⇐
mutationFnدرخواست شبکه
⇐
onSuccessپاسخ موفق
onErrorخطا (بعد از retryها)
⇐
onSettledدر هر دو حالت — پاک‌سازی

ترتیب اجرا: کالبک‌های خود mutation اول اجرا می‌شوند و بعد کالبک‌های component-level همان فراخوانی (اگر در mutate(vars, { onSuccess }) داده باشید). در تمرین‌های تیمی معمولاً منطق اصلی را در هوک می‌گذاریم و موارد UI-محلی (toast، بستن مودال) را در متد mutate.

invalidation: بعد از تغییر، داده را «کهنه» کن

دو راه برای به‌روز نگه‌داشتن کش بعد از mutation:

  1. Invalidation (پیش‌فرض حرفه‌ای): بگو «دادهٔ X دیگر قابل اعتماد نیست». Queryهای متناظر stale می‌شوند و اگر observer فعال داشته باشند بلافاصله refetch می‌گیرند.
  2. setQueryData دستی: پاسخ سرور را مستقیم در کش بنویس — سریع اما مسئولیت شکل‌دادن به داده با شماست.
دو الگو، پهلو به پهلوjs
// الگوی ۱: invalidation — ساده، همیشه درست
onSuccess: () => {
  queryClient.invalidateQueries({ queryKey: ['posts'] })
}

// الگوی ۲: نوشتن مستقیم پاسخ سرور در کش
onSuccess: (saved) => {
  queryClient.setQueryData(['post', saved.id], saved)
  queryClient.invalidateQueries({ queryKey: ['posts'] }) // لیست همچنان refetch
}

انتخاب: برای «لیست‌ها» invalidation (سرور منبع حقیقت است)، برای «جزئیات همان آیتم» می‌توانید setQueryData (پاسخ را دارید، چرا دوباره بگیریم؟). ترکیب هر دو رایج و سالم است.

به‌روزرسانی خوش‌بینانه (Optimistic Update)

ایده: تغییر را فوراً در کش بنویس (خوش‌بین باش) تا UI آنی شود؛ اگر سرور جواب خطا داد، به حالت قبل برگرد. الگوی رسمی نسخهٔ ۵:

src/components/PostRow.jsx — حذف خوش‌بینانهjsx
import { useMutation, useQueryClient } from '@tanstack/react-query'
import { api } from '../lib/api'

export default function DeletePostButton({ id }) {
  const queryClient = useQueryClient()

  const removePost = useMutation({
    mutationFn: (id) => api.deletePost(id),

    // ۱) قبل از درخواست: نسخهٔ فعلی را ذخیره کن و کش را آپدیت کن
    onMutate: async (id) => {
      await queryClient.cancelQueries({ queryKey: ['posts'] }) // refetch در جریان را متوقف کن
      const previous = queryClient.getQueryData(['posts'])      // snapshot
      queryClient.setQueryData(['posts'], (old) =>
        old?.filter((p) => p.id !== id) ?? old
      )
      return { previous } // به context کالبک‌های بعدی می‌رسد
    },

    // ۲) خطا: برگرد به snapshot
    onError: (err, id, context) => {
      queryClient.setQueryData(['posts'], context.previous)
      alert('حذف ناموفق بود؛ بازگردانی شد.')
    },

    // ۳) در هر حالت: همیشه با سرور sync کن
    onSettled: () => {
      queryClient.invalidateQueries({ queryKey: ['posts'] })
    },
  })

  return (
    <button disabled={removePost.isPending} onClick={() => removePost.mutate(id)}>
      {removePost.isPending ? '...' : 'حذف'}
    </button>
  )
}

سه گام طلایی که حفظ کنید:

  1. onMutate: cancel + snapshot + setQueryData + برگرداندن { previous }.
  2. onError: بازگردانی از context.previous.
  3. onSettled: invalidation برای همگام‌شدن با حقیقتِ سرور.
هشدار — cancelQueries را حذف نکنید

اگر قبل از setQueryData، یک refetch در جریان باشد، وقتی تمام شود دادهٔ قدیمی را روی تغییر خوش‌بینانه‌تان می‌نویسد و حذفِ آیتم «برمی‌گردد». اول cancel، بعد snapshot، بعد set.

mutationهای هماهنگ با هم: useMutationState

برای نمایش وضعیت‌های جهانی (مثلاً badge «N تغییر در حال ذخیره») لازم نیست وضعیت را جابه‌جا کنید؛ Query خودش همهٔ mutationها را نگه می‌دارد:

شمارش mutationهای در جریانjsx
import { useMutationState } from '@tanstack/react-query'

function SavingBadge() {
  const saving = useMutationState({
    filters: { status: 'pending' },
    select: (m) => m,
  })
  if (saving.length === 0) return null
  return <span className="badge">{saving.length} تغییر ذخیره می‌شود...</span>
}

جمع‌بندی فصل

  • mutation دستی اجرا می‌شود: useMutation({ mutationFn }) + .mutate(variables).
  • چرخه: onMutate → mutationFn → onSuccess/onError → onSettled.
  • بعد از هر mutation: invalidation (پیش‌فرض) یا setQueryData (پاسخ قطعی).
  • الگوی خوش‌بینانه: cancelQueries + getQueryData/setQueryData + rollback در onError + invalidate در onSettled.
  • useMutationState وضعیت‌های سراسری را بدون state اضافه می‌دهد.
تمرین فصل ۱۰

۱) فرم ویرایش پست بسازید (PATCH با api.updatePost) که بعد از موفقیت، هم جزئیات ['post', id] را با setQueryData آپدیت کند و هم لیست را invalidate کند. ۲) افزودن پست را خوش‌بینانه کنید: اول با id موقت (مثلاً Date.now()) در لیست بگذارید و بعد از موفقیت invalidate کنید. ۳) با DevTools ببینید بعد از هر mutation، Queryهای stale چطور دوباره fetch می‌شوند.
