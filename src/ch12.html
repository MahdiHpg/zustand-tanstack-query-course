امکانات پیشرفته — صفحه‌بندی، Infinite و Suspense

صفحه‌بندی نرم با placeholderData، اسکرول بی‌نهایت با useInfiniteQuery، Suspense خالص با useSuspenseQuery، کوئری‌های موازی داینامیک و اتصال به شبکهٔ آفلاین.

در این فصل یاد می‌گیرید

  • صفحه‌بندی بدون فلش با placeholderData: keepPreviousData
  • useInfiniteQuery با initialPageParam و getNextPageParam
  • رندر اعلامی با useSuspenseQuery و ErrorBoundary
  • کوئری‌های داینامیک با useQueries و رفتار آفلاین

صفحه‌بندی با UI ثابت

مشکل کلاسیک صفحه‌بندی: با هر تغییر صفحه، لیست خالی و دوباره پر می‌شود؛ اسکرول می‌پرد و کاربر گیج می‌شود. راه‌حل: تا دادهٔ صفحهٔ جدید نیامده، دادهٔ صفحهٔ قبلی را «نمایشی» نگه دار:

src/components/PaginatedPosts.jsxjsx
import { useState } from 'react'
import { useQuery, keepPreviousData } from '@tanstack/react-query'
import { api } from '../lib/api'
import { postKeys } from '../features/posts/keys'

export default function PaginatedPosts() {
  const [page, setPage] = useState(1)

  const { data, isPlaceholderData, isFetching } = useQuery({
    queryKey: postKeys.list({ page }),
    queryFn: ({ signal }) => api.posts(`?_page=${page}&_limit=10`, signal),
    placeholderData: keepPreviousData, // ← ستارهٔ ماجرا
    staleTime: 30_000,
  })

  return (
    <div style={{ opacity: isPlaceholderData ? 0.6 : 1 }}>
      <ul>{data?.map((p) => <li key={p.id}>{p.title}</li>)}</ul>
      <div>
        <button onClick={() => setPage((p) => p - 1)} disabled={page === 1}>قبلی</button>
        <button onClick={() => setPage((p) => p + 1)}>بعدی</button>
        {isFetching && !isPlaceholderData && <span>در حال آوردن صفحهٔ جدید...</span>}
      </div>
    </div>
  )
}

نکته‌ها: data در حین fetch صفحهٔ بعد، هنوز صفحهٔ قبلی است (isPlaceholderData: true)؛ با opacity کم، حس «در حال تغییر» می‌دهیم بدون خالی‌شدن لیست. هر صفحه وقتی گرفته شد، در کشِ کلید خودش می‌ماند و برگشت به صفحهٔ قبل آنی است.

useInfiniteQuery — اسکرول بی‌نهایت

برای «بارگذاری بیشتر»، ساختار داده فرق می‌کند: پاسخ شامل چند صفحه و نشانگرِ صفحهٔ بعد (cursor) است. سه ورودی اجباری در نسخهٔ ۵:

src/components/InfinitePosts.jsxjsx
import { useInfiniteQuery } from '@tanstack/react-query'
import { api } from '../lib/api'
import { postKeys } from '../features/posts/keys'

export default function InfinitePosts() {
  const { data, isPending, isError, fetchNextPage, hasNextPage, isFetchingNextPage } =
    useInfiniteQuery({
      queryKey: postKeys.lists(), // یا list({ q }) برای فیلترها
      queryFn: ({ signal, pageParam }) => api.posts(`?_limit=10&_page=${pageParam}`, signal),
      initialPageParam: 1,
      getNextPageParam: (lastPage, allPages, lastPageParam) => {
        // JSONPlaceholder: اگر صفحهٔ آخر کمتر از ۱۰ آیتم داشت یعنی تمام
        return lastPage.length < 10 ? undefined : lastPageParam + 1
      },
      maxPages: 5, // حداکثر ۵ صفحه در کش بماند (حافظهٔ موبایل!)
    })

  if (isPending) return <p>بارگذاری...</p>
  if (isError) return <p>خطا!</p>

  // data.pages آرایه‌ای از «پاسخ هر صفحه» است
  const posts = data.pages.flat()

  return (
    <div>
      {posts.map((p) => (
        <article key={p.id}><h4>{p.title}</h4></article>
      ))}
      <button
        onClick={() => fetchNextPage()}
        disabled={!hasNextPage || isFetchingNextPage}
      >
        {isFetchingNextPage
          ? 'در حال بارگذاری...'
          : hasNextPage
            ? 'بارگذاری بیشتر'
            : 'همه را دیدید'}
      </button>
    </div>
  )
}
  • getNextPageParam: از پاسخ آخرین صفحه بگویید صفحهٔ بعد چیست؛ برگرداندن undefined یعنی تمام (hasNextPage: false). اگر API شما cursor در پاسخ می‌دهد (lastPage.nextCursor)، همان را برگردانید.
  • data.pages آرایهٔ صفحات است؛ با data.pageParams هم نشانگرها را دارید.
  • maxPages (جدید در v5) کش صفحات قدیمی را می‌بُرد تا اپ در لیست‌های خیلی بلند از حافظه نترکد.
نکته — اتصال به IntersectionObserver

برای «اسکرول خودکار» به‌جای دکمه، در production با @tanstack/react-virtual یا یک div sentinel و IntersectionObserver ترکیب کنید: if (entry.isIntersecting && hasNextPage) fetchNextPage(). دقت کنید fetchNextPage را در خود کالبک observer صدا می‌زنید، نه در رندر!

useSuspenseQuery — رندر اعلامی

اگر معماری team تان React 18+ و Suspense است، useSuspenseQuery کامپوننت را از تمام ifهای وضعیت خلاص می‌کند: داده همیشه تعریف‌شده است (بدون data?.x) و حالت‌های pending/error به مرزهای Suspense/ErrorBoundary منتقل می‌شوند:

src/components/PostDetailSuspense.jsxjsx
import { Suspense } from 'react'
import { useSuspenseQuery, ErrorBoundary } from '@tanstack/react-query'
import { api } from '../lib/api'
import { postKeys } from '../features/posts/keys'

function PostDetail({ id }) {
  const { data: post } = useSuspenseQuery({
    queryKey: postKeys.detail(id),
    queryFn: ({ signal }) => api.post(id, signal),
  })
  // اینجا data همیشه هست؛ هیچ isPendingی وجود ندارد
  return <h1>{post.title}</h1>
}

export default function Page({ id }) {
  return (
    <ErrorBoundary fallbackRender={({ error }) => <p>خطا: {error.message}</p>}>
      <Suspense fallback={<p>در حال بارگذاری...</p>}>
        <PostDetail id={id} />
      </Suspense>
    </ErrorBoundary>
  )
}
هشدار — کلید باید زیر Suspense باشد

کامپوننتی که useSuspenseQuery دارد باید داخل مرز Suspense رندر شود، وگرنه کل مسیر تا نزدیک‌ترین Suspense بالا معلق می‌شود و کل صفحه لودینگ می‌گیرد. مرزها را دانه‌درشت نه، ولی مرتب بگذارید.

کوئری‌های موازی و داینامیک: useQueries

چند useQuery کنار هم خودبه‌خود موازی اجرا می‌شوند. اما وقتی «تعداد» کوئری‌ها داینامیک است (مثلاً جزئیات N کاربر انتخابی)، تعداد هوک‌ها ثابت نمی‌ماند — قانون هوک‌ها می‌شکند. راه‌حل رسمی:

N کوئری با یک هوکjsx
import { useQueries } from '@tanstack/react-query'
import { api } from '../lib/api'
import { userKeys } from '../features/users/keys'

function UserCards({ userIds }) {
  const results = useQueries({
    queries: userIds.map((id) => ({
      queryKey: userKeys.detail(id),
      queryFn: ({ signal }) => api.user(id, signal),
      staleTime: 5 * 60_000,
    })),
  })

  return (
    <div>
      {results.map((r, i) =>
        r.isPending ? (
          <p key={userIds[i]}>...</p>
        ) : (
          <Card key={userIds[i]} user={r.data} />
        )
      )}
    </div>
  )
}

شبکهٔ ناپایدار: networkMode

پیش‌فرض: بدون اینترنت، Queryها متوقف (paused) می‌شوند و با برگشتن شبکه دوباره اجرا می‌شوند — با fetchStatus: 'paused' می‌توانید بنر «آفلاین» نشان دهید. سه حالت:

networkModeرفتارکاربرد
online (پیش‌فرض)بدون شبکه متوقف می‌شوداکثر Queryها
offlineFirstیک بار امتحان می‌کند، بعد صف می‌شودداده‌های کش‌شده در SW
alwaysهمیشه اجرا؛ شبکه مهم نیستداده‌های کاملاً محلی

DevTools حرفه‌ای

افزونهٔ ReactQueryDevtools (که در فصل ۸ نصب کردیم) بیش از نمایش لیست است:

  • وضعیت هر Query (fresh/stale/paused)، زمان آخرین fetch و تعداد observerها را می‌بینید.
  • دکمهٔ invalidate/refetch/reset/copy برای هر Query — دیباگ بدون دست زدن به کد.
  • ساختار درختی کلیدها نشان می‌دهد factory شما درست کار می‌کند یا کلیدها قاطی شده‌اند.
  • در production غیرفعال است؛ فقط dev bundle شامل آن است.

جمع‌بندی فصل

  • صفحه‌بندی نرم = placeholderData: keepPreviousData + کلید پارامتری.
  • Infinite = initialPageParam + getNextPageParam (undefined یعنی تمام) + maxPages.
  • Suspense = useSuspenseQuery داخل مرز Suspense/ErrorBoundary؛ data همیشه هست.
  • کوئری داینامیک = useQueries با آرایهٔ پارامترها.
  • آفلاین با fetchStatus: 'paused' قابل مدیریت است؛ DevTools ابزار روزمرهٔ دیباگ کش است.
تمرین فصل ۱۲

۱) PaginatedPosts را طوری ارتقا دهید که صفحهٔ بعد را پیش‌واکشی کند (سرنخ: در onSuccessِ پایان fetch یا در effect با شرط !isPlaceholderData، prefetchQuery صفحهٔ بعد). ۲) نسخهٔ Infinite را با دکمه بسازید و بعد با IntersectionObserver خودکارش کنید. ۳) سناریوی آفلاین را تست کنید: DevTools → Network → Offline، بعد برگردید و رفتار paused→refetch را در DevTools ببینید.
