Zustand از صفر — نصب و اولین استور

از نصب تا ساخت اولین استور واقعی: State، اکشن‌ها و مصرف آن‌ها در کامپوننت — بدون حتی یک Provider.

در این فصل یاد می‌گیرید

  • نصب Zustand در یک پروژهٔ Vite و ساخت اولین استور
  • آناتومی create: چرا استور، «هوک» است؟
  • نوشتن اکشن‌ها و فراخوانی آن‌ها در UI
  • قوانین نام‌گذاری و سازماندهی فایل استورها از روز اول

راه‌اندازی پروژه

برای تمرین‌های بخش اول یک پروژهٔ React ساده با Vite می‌سازیم (اگر پروژهٔ آماده دارید، از همان استفاده کنید):

terminalbash
npm create vite@latest zustand-lab -- --template react
cd zustand-lab
npm install
npm install zustand        # نسخهٔ ۵ را نصب می‌کند
npm run dev
نکته

Zustand به هیچ Wrapper (مثل QueryClientProvider یا Provider ریداکس) نیاز ندارد. وابستگی واحدش خود React است؛ یعنی حتی می‌توانید آن را در پروژه‌های غیر React هم استفاده کنید.

اولین استور: شمارنده

کلاسیک‌ترین شروع. یک فایل جدید بسازید: src/store/useCounterStore.js

src/store/useCounterStore.jsjs
import { create } from 'zustand'

// create یک «هوک» برمی‌گرداند؛ به همین دلیل اسمش را با use شروع می‌کنیم
export const useCounterStore = create((set) => ({
  // ۱) State اولیه
  count: 0,

  // ۲) اکشن‌ها: توابعی که State را تغییر می‌دهند
  increment: () => set((state) => ({ count: state.count + 1 })),
  decrement: () => set((state) => ({ count: state.count - 1 })),
  reset: () => set({ count: 0 }),
}))

سه نکتهٔ بنیادی در همین ۱۰ خط هست:

  • create(callback) یک هوک سفارشی برمی‌گرداند که هر جای برنامه قابل استفاده است — بدون Provider و بدون Context.
  • شیء برگشتیِ callback ترکیبی از داده (اینجا count) و اکشن‌ها (اینجا increment و...) است. در Zustand هیچ اجباری به جداسازی این دو نیست — حتی توصیه هم می‌شود کنار هم بمانند.
  • set مثل setState در React کار می‌کند: اگر یک شیء جزئی بدهید، فقط همان کلیدها با merge به‌روزرسانی می‌شوند و بقیهٔ State دست‌نخورده می‌ماند.

مصرف در کامپوننت

src/App.jsxjsx
import { useCounterStore } from './store/useCounterStore'

export default function App() {
  // مقدار count را «انتخاب» می‌کنیم (selector)
  const count = useCounterStore((s) => s.count)
  const increment = useCounterStore((s) => s.increment)

  return (
    <main>
      <h1>{count}</h1>
      <button onClick={increment}>+1</button>
    </main>
  )
}

کامپوننت با useCounterStore((s) => s.count) می‌گوید: «من فقط به count کار دارم». نتیجه: اگر بعداً قسمت دیگری از استور تغییر کند، این کامپوننت اصلاً رندر نمی‌شود. (در فصل ۴ به‌عمق این موضوع می‌رویم.)

هشدار — فراخوانی هوک بدون سلکتور

اگر بنویسید const state = useCounterStore() بدون آرگومان، کل استور subscribe می‌شود و هر تغییر، رندر دوباره می‌گیرد. در Zustand نسخهٔ ۴ این شکل مجاز بود؛ از نسخهٔ ۵ استفاده از آن بدون سلکتور فقط برای State ثابت (مثل مقادیر اولیه) مجاز است. عادت کنید: همیشه سلکتور بنویسید.

استور واقعی‌تر: اطلاعات کاربر

یک استور با دادهٔ شیء‌ای و چند اکشن واقعی، تا merge و تغییر تو در تو را ببینید:

src/store/useUserStore.jsjs
import { create } from 'zustand'

const guest = { name: '', email: '', loggedIn: false }

export const useUserStore = create((set) => ({
  user: guest,
  lastAction: null,

  login: (user) => set({ user: { ...user, loggedIn: true }, lastAction: 'login' }),

  logout: () => set({ user: guest, lastAction: 'logout' }),

  // به‌روزرسانی فقط یک فیلد از شیء تو در تو
  rename: (name) =>
    set((state) => ({
      user: { ...state.user, name },
      lastAction: 'rename',
    })),
}))
src/Profile.jsxjsx
import { useState } from 'react'
import { useUserStore } from './store/useUserStore'

export default function Profile() {
  const user = useUserStore((s) => s.user)
  const login = useUserStore((s) => s.login)
  const rename = useUserStore((s) => s.rename)

  const [name, setName] = useState('')

  if (!user.loggedIn) {
    return <button onClick={() => login({ name: 'مهدی', email: 'm@example.com' })}>ورود</button>
  }

  return (
    <div>
      <p>سلام {user.name}! ({user.email})</p>
      <input value={name} onChange={(e) => setName(e.target.value)} placeholder="نام جدید" />
      <button onClick={() => rename(name)}>تغییر نام</button>
    </div>
  )
}

دقت کنید: rename شیء user را با spread بازسازی می‌کند و فقط name را عوض می‌کند. Zustand مثل React به immutability پایبند است؛ هر تغییر یعنی ساخت نسخهٔ جدید از همان قسمت. (فصل ۵ نشان می‌دهد چطور با immer، این نوشتن را ساده کنیم.)

set — دو صورت کاربرد

صورتمثالکی استفاده کنیم؟
شیء جزئی (Partial)set({ count: 0 })وقتی مقدار جدید به State فعلی وابسته نیست
تابع آپدیترset((s) => ({ count: s.count + 1 }))وقتی به State فعلی نیاز دارید — همیشه امن‌تر است چون اگر دو آپدیت پشت‌سرهم برسند، از آخرین نسخهٔ State حساب می‌کند
ممنوع — جهش (Mutation) مستقیم

set((s) => { s.count++ ; return s }) یعنی جهش State موجود؛ React متوجه تغییر نمی‌شود، مقایسهٔ مرجع خراب می‌شود و باگ‌های «رندر نمی‌شود» تولید می‌کند. همیشه یک شیء جدید برگردانید. (فقط در فصل ۵ با میان‌افزار immer قانونی می‌شود.)

سازماندهی فایل‌ها از روز اول

یک قرارداد ساده که در تیم‌ها جواب می‌دهد: برای هر دامنهٔ مستقل، یک فایل استور با پیشوند use:

ساختار پیشنهادیtext
src/
├── store/
│   ├── useCounterStore.js
│   ├── useUserStore.js
│   └── useCartStore.js      # فصل ۷ همین را کامل می‌کنیم
├── components/
└── App.jsx
  • اسم استور = use + نام دامنه + Store (مثلاً useCartStore).
  • هر استور فقط مسئول دامنهٔ خودش است؛ «استور مادرِ همه‌چیز» نسازید — همین باعث فساد State می‌شود.
  • اکشن‌ها را با فعل نام‌گذاری کنید: addItem، clearCart، toggleTheme.

جمع‌بندی فصل

  • create یک هوک برمی‌گرداند؛ بدون Provider در هر کامپوننتی مصرف می‌شود.
  • استور = دادهٔ اولیه + اکشن‌ها، کنار هم؛ اکشن‌ها با فعل نام‌گذاری می‌شوند.
  • در کامپوننت همیشه با سلکتور بخوانید: useXStore((s) => s.x).
  • set دو صورت دارد: شیء جزئی یا تابع آپدیتر؛ برای State وابسته، تابع آپدیتر.
  • هرگز State را جهش ندهید؛ نسخهٔ جدید بسازید.
تمرین فصل ۲

یک استور useThemeStore بسازید با State theme: 'light' | 'dark' و اکشن toggleTheme. در اپ یک دکمه بگذارید که تم را عوض می‌کند و رنگ پس‌زمینهٔ صفحه را بر اساس State عوض کنید. بعد یک استور useTodoStore با آرایهٔ todos و سه اکشن addTodo، removeTodo و toggleTodo بنویسید و یک لیست‌کار ساده بسازید — بدون هیچ prop drillingی.

در فصل بعد: عمق API استور — پارامتر get، اکشن‌های async و خواندن/نوشتن State از بیرونِ دنیای React (در interceptorها و توابع کمکی).
