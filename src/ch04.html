Selectors و بهینه‌سازی رندر

سلکتور قلب کارایی Zustand است. در این فصل یاد می‌گیرید دقیقاً چه چیزی باعث رندر می‌شود، چرا برگرداندن شیءِ جدید از سلکتور خطرناک است و با useShallow و Transient Updates چطور حرفه‌ای بنویسیم.

در این فصل یاد می‌گیرید

  • مکانیزم subscribe و مقایسهٔ Object.is
  • چرا (s) => ({ a: s.a, b: s.b }) باگ رندر می‌سازد؟
  • استفادهٔ صحیح از useShallow
  • Transient Updates: خواندن و اجرا بدون رندر

چه چیزی باعث رندر می‌شود؟

وقتی می‌نویسید:

مکانیزم سلکتورjs
const price = useProductStore((s) => s.price)

پشت صحنه این اتفاق می‌افتد: کامپوننت در استور subscribe می‌شود. هر بار استور تغییر می‌کند، Zustand سلکتور شما را با State جدید دوباره اجرا می‌کند و نتیجه را با نتیجهٔ قبلی مقایسه می‌کند — با Object.is. اگر برابر باشند، رندری در کار نیست. اگر متفاوت باشند، کامپوننت رندر می‌شود.

پس قانون کارایی Zustand یک جمله است: سلکتور شما باید برای دادهٔ تغییرنکرده، همیشه «همان مقدار» (برابر از نظر Object.is) را برگرداند.

مقادیر اولیه امن‌اند؛ مقادیر مرجعی خطر

سلکتورنوع خروجیهر تغییر استور باعث رندر؟
(s) => s.countعدد/رشته/بولینفقط وقتی خودش عوض شود — امن
(s) => s.user.nameرشتهفقط وقتی name عوض شود — امن
(s) => s.itemsمرجع آرایهفقط وقتی مرجع آرایه عوض شود — امن
(s) => s.items.map(...)آرایهٔ جدیدهمیشه! — باگ رندر
(s) => ({ a: s.a, b: s.b })شیء جدیدهمیشه! — باگ رندر

مقایسهٔ Object.is برای اعداد و رشته‌ها «ارزشی» است، اما برای آرایه و شیء «مرجعی»: هر اجرای s.items.map(...) یک آرایهٔ جدید در حافظه می‌سازد که هرگز با قبلی برابر نیست؛ پس هر تغییر استور (حتی تغییر یک فیلد بی‌ربط) رندر می‌گیرد. بدتر: چون خود State هم هر بار عوض می‌شود، در برخی سناریوها حلقهٔ بی‌نهایت رندر می‌سازد.

راه‌حل ۱: سلکتورهای کوچک و متعدد

به‌جای یک سلکتورِ شیءساز، چند سلکتور مجزا:

بد — شیء جدید در هر رندرjsx
const { name, email } = useUserStore(
  (s) => ({ name: s.user.name, email: s.user.email })
)
خوب — دو subscribe مستقلjsx
const name = useUserStore((s) => s.user.name)
const email = useUserStore((s) => s.user.email)

فراتر از درستی: این شکل هم دقیق‌تر است (فقط تغییر name رندر می‌گیرد، نه تغییر email) هم خواناتر.

راه‌حل ۲: useShallow — مقایسهٔ سطحی

گاهی واقعاً چند فیلد را یک‌جا می‌خواهید (مثلاً در یک map یا بازگشت از یک تابع کمکی). برای این موارد Zustand یک هوک کمکی دارد که خروجی سلکتور را سطحی مقایسه می‌کند: کلیدها و مقادیر اولیهٔ برابر = برابر.

src/store/useCartStore.js و کامپوننتjsx
import { useShallow } from 'zustand/react/shallow'
import { useCartStore } from './useCartStore'

function CartSummary() {
  const { items, coupon } = useCartStore(
    useShallow((s) => ({ items: s.items, coupon: s.coupon }))
  )
  // فقط وقتی مرجعِ items یا مقدار coupon عوض شود رندر می‌گیرد
  return <span>{items.length} قلم — کوپن: {coupon}</span>
}
هشدار — shallow یعنی سطحی، نه عمیق

useShallow فقط یک سطح مقایسه می‌کند. اگر سلکتور هر بار محتوای جدیدی بسازد (مثل s.items.map(i => i.id * 2)) که عناصرش آرایه/شیء تازه‌اند، باز هم هر بار متفاوت است. برای دادهٔ محاسبه‌شدهٔ سنگین، راه‌حل درست useMemo در کامپوننت یا سلکتورِ ذخیره‌شده در استور است.

نکته — تفاوت با نسخهٔ ۴

در نسخهٔ ۴ آرگومان دوم هوک را برابر shallow می‌گذاشتند: useStore(selector, shallow). این API در نسخهٔ ۵ حذف شده و به‌جایش useShallow دور سلکتور پیچیده می‌شود. در مصاحبه‌ها هم می‌پرسند!

محاسبات مشتق‌شده: کجا انجام شود؟

مجموع قیمت سبد از دادهٔ خام مشتق می‌شود. سه جای ممکن:

  • در استور، هنگام هر mutation (نگه‌داشتن total در State): سریع ولی تکرار اطلاعات و ریسک ناهماهنگی — معمولاً نه.
  • در سلکتور: (s) => s.items.reduce(...) — هر اجرا عدد جدیدی «ارزشی» می‌سازد پس رندر مشکل شیء را ندارد؛ اما محاسبه در هر تغییر استور اجرا می‌شود.
  • در کامپوننت با useMemo: فقط وقتی مرجع items عوض شود محاسبه می‌شود — انتخاب پیش‌فرض برای محاسبات سنگین.
src/CartTotal.jsxjsx
import { useMemo } from 'react'
import { useCartStore } from './store/useCartStore'

export default function CartTotal() {
  const items = useCartStore((s) => s.items)

  // فقط وقتی آرایهٔ items عوض شود دوباره حساب می‌شود
  const total = useMemo(
    () => items.reduce((sum, i) => sum + i.price * i.qty, 0),
    [items]
  )

  return <div>جمع کل: {total.toLocaleString('fa-IR')} تومان</div>
}

Transient Updates: بدون رندر با State کار کن

گاهی State تغییری می‌کند که اصلاً نباید UI را رندر کند: موقعیت موس، مقدار اسکرول، تایمر... برای این‌ها subscribe و getState بدون هوک استفاده می‌شود:

src/MousePad.jsx — رندر صفر در هر حرکتjsx
import { useRef, useEffect } from 'react'
import { useMouseStore } from './store/useMouseStore'

export default function MousePad() {
  const ref = useRef(null)

  useEffect(() => {
    // ۱) نوشتن: هر حرکت موس را در استور ذخیره کن — بدون setState در React
    const onMove = (e) => useMouseStore.setState({ x: e.clientX, y: e.clientY })
    window.addEventListener('mousemove', onMove)

    // ۲) خواندن: DOM را مستقیم آپدیت کن، نه با رندر React
    const unsubscribe = useMouseStore.subscribe((s) => {
      if (ref.current) {
        ref.current.style.transform = `translate(${s.x}px, ${s.y}px)`
      }
    })

    return () => {
      window.removeEventListener('mousemove', onMove)
      unsubscribe()
    }
  }, [])

  return <div ref={ref} className="cursor-dot" />
}

و اگر فقط در یک رویداد به مقدار لحظه‌ای نیاز دارید، اصلاً subscribe لازم نیست:

خواندن در لحظهٔ نیازjs
const handleSave = () => {
  const { draft } = useEditorStore.getState() // بدون رندر، بدون سلکتور
  saveToServer(draft)
}

چک‌لیست کارایی سلکتورها

  • پیش‌فرض: سلکتورِ مقدار اولیهٔ تکی — (s) => s.a.b.
  • هیچ‌وقت شیء/آرایهٔ تازه داخل سلکتور نسازید.
  • چند فیلد؟ یا چند سلکتور، یا useShallow — نه object literal خام.
  • محاسبهٔ سنگین؟ useMemo در کامپوننت روی مرجعِ پایدار.
  • State پرتغییر و بی‌نیاز از رندر؟ Transient pattern با setState/subscribe.
  • برای راستی‌آزمایی، از tab «Profiler» در React DevTools استفاده کنید و تعداد رندرها را ببینید.

جمع‌بندی فصل

  • رندر وقتی اتفاق می‌افتد که خروجی سلکتور با Object.is تغییر کرده باشد.
  • شیء/آرایهٔ تازه در سلکتور = رندر اضافه = باگ کلاسیک Zustand.
  • useShallow از zustand/react/shallow مقایسهٔ سطحی می‌دهد؛ در v5 جایگزین آرگومان دوم هوک است.
  • محاسبات مشتق‌شده را با useMemo در کامپوننت انجام دهید.
  • Transient Updates برای دادهٔ پرتغییرِ بی‌نیاز از رندر: getState و setState مستقیم.
تمرین فصل ۴

در پروژهٔ تمرینی یک استور بسازید که هر ۱۰۰ میلی‌ثانیه یک شمارنده را افزایش دهد (با setInterval و setState). دو کامپوننت بسازید: یکی با سلکتور معمولی مقدار شمارنده (که رندر می‌شود) و یکی که با Transient pattern فقط عدد را داخل ref آپدیت می‌کند. با React DevTools Profiler تفاوت تعداد رندرها را ثبت کنید و در یک پاراگراف توضیح دهید هر کدام کجا مناسب است.
