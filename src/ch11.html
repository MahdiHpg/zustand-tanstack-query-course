Query Keys و مدیریت کش

کلید، شناسنامهٔ داده در کش است. در این فصل الگوی رسمی Query Key Factory، اینولیدیشن هدفمند با فیلترها، prefetch و ابزارهای دستوری QueryClient را یاد می‌گیرید.

در این فصل یاد می‌گیرید

  • قواعد ساخت کلید و چرا ترتیب عناصر مهم است
  • الگوی Query Key Factory + هوک queryOptions برای تایپ ایمن
  • invalidate با تطبیق جزئی/دقیق و predicate
  • prefetchQuery، ensureQueryData، cancelQueries و بقیهٔ ابزارها

قواعد کلیدنویسی

کلید آرایه است و از چپ به راست، از عمومی به خاص:

سلسله‌مراتب کلیدjs
['posts']                         // همهٔ پست‌ها
['posts', 'list']                 // لیست
['posts', 'list', { page: 2, q: 'react' }]  // لیست با پارامتر
['posts', 'detail', 5]            // جزئیات پست ۵
['posts', 'detail', 5, 'comments']// کامنت‌های پست ۵

سه قاعده:

  • متجانس و سلسله‌مراتبی: هر بخش، پدرِ بخش بعدی است تا تطبیق جزئی (بعداً) معنا داشته باشد.
  • serialize‌پذیر: فقط رشته/عدد/بولین/آرایه/شیء ساده. کلید { page: 2, q: 'react' } با { q: 'react', page: 2 } برابر است (هش پایدار با ترتیب کلیدهای مرتب‌شده).
  • متغیرها داخل کلید: هر چیزی که خروجی را تغییر می‌دهد (پارامترها، زبان، نقش کاربر) باید در کلید باشد.
ممنوع — کلید بی‌پارامتر برای دادهٔ پارامتری

اگر جستجوی کاربر را در State نگه دارید ولی کلید ثابت ['posts'] باشد، همهٔ جستجوها روی یک داده نوشته می‌شوند! پارامتر باید در کلید باشد: ['posts', 'list', { q }].

الگوی Query Key Factory

رشته‌های تکراری در کل پروژه = تلهٔ غلط املایی. راه‌حل رسمی مستندات، یک آبجکت کارخانه برای هر دامنه:

src/features/posts/keys.jsjs
export const postKeys = {
  all: ['posts'],
  lists: () => [...postKeys.all, 'list'],
  list: (filters) => [...postKeys.lists(), filters],
  details: () => [...postKeys.all, 'detail'],
  detail: (id) => [...postKeys.details(), id],
  comments: (id) => [...postKeys.detail(id), 'comments'],
}

// مصرف:
queryKey: postKeys.list({ page: 1, q: 'react' })   // ['posts','list',{...}]
queryKey: postKeys.detail(5)                        // ['posts','detail',5]

جادوی این ساختار در invalidate است — از عمومی به خاص، هر سطحی را می‌توانید هدف بگیرید:

قدرت سلسله‌مراتبjs
qc.invalidateQueries({ queryKey: postKeys.all })       // همهٔ چیزِ پست‌ها
qc.invalidateQueries({ queryKey: postKeys.lists() })   // فقط لیست‌ها، نه جزئیات
qc.invalidateQueries({ queryKey: postKeys.detail(5) }) // فقط پست ۵ (+کامنت‌هایش)

queryOptions: کلید + queryFn در یک جا (نسخهٔ ۵)

هوک کمکی queryOptions تعریف کوئری را به یک آبجکت قابل استفاده در همهٔ هوک‌ها تبدیل می‌کند و تایپ data را هم حفظ می‌کند:

src/features/posts/queries.js — TSts
import { queryOptions } from '@tanstack/react-query'
import { postKeys } from './keys'

export const postQueries = {
  list: (filters: { page: number; q?: string }) =>
    queryOptions({
      queryKey: postKeys.list(filters),
      queryFn: ({ signal }) => api.posts(filters, signal),
      staleTime: 30_000,
    }),

  detail: (id: number) =>
    queryOptions({
      queryKey: postKeys.detail(id),
      queryFn: ({ signal }) => api.post(id, signal),
    }),
}

// مصرف — تایپ data دقیقاً Post[] است، بدون تعریف دستی:
const { data } = useQuery(postQueries.list({ page: 1 }))
qc.invalidateQueries({ queryKey: postKeys.all })

invalidateQueries و فیلترها

فراخوانیاثر
invalidateQueries({ queryKey: postKeys.all })همهٔ Queryهایی که کلیدشان با ['posts'] شروع می‌شود.
invalidateQueries({ queryKey: postKeys.lists(), exact: true })فقط کلید دقیقاً برابر — بدون زیرمجموعه‌ها.
invalidateQueries({ predicate: (q) => q.queryKey[0] === 'posts' && q.state.dataUpdatedAt > hourAgo })فیلتر کامل با تابع — برای شرایط پیچیده.
refetchQueries({ queryKey: postKeys.all })بدون stale کردن، مستقیم refetch.

invalidate یعنی: stale کن + اگر observer فعال دارد فوراً refetch، وگرنه فقط برای mount بعدی آمادهٔ refetch باش. به یاد داشته باشید: invalidate هیچ چیز را حذف نمی‌کند؛ دادهٔ قدیمی تا refetch بعدی همان‌جاست.

ابزارهای دستوری QueryClient

متدکاربرد واقعی
getQueryData(key)خواندن کش (مثلاً snapshot در onMutate)
setQueryData(key, updater)نوشتن کش — updater مثل setState تابعی است و undefined را نگه می‌دارد
prefetchQuery({ queryKey, queryFn })گرفتن قبل از نیاز (hover روی لینک، mount والد) — خطاها بی‌صدا رد می‌شوند
ensureQueryData(key)اگر تازه در کش نیست بگیر و Promise بده — در لودرهای روتر عالی است
cancelQueries(filters)لغو درخواست‌های در جریان — در onMutate خوش‌بینانه
removeQueries(filters)حذف کامل از کش (مثلاً خروج کاربر)
qc.clear()پاک‌سازی کل کش
getQueryState(key) / qc.getQueryCache().findAll()دیباگ و ابزارهای reporting
پیش‌واکشی هوشمند: وقتی روی لینک hover شدjsx
function PostLink({ id }) {
  const qc = useQueryClient()
  const prefetch = () => qc.prefetchQuery(postQueries.detail(id))

  return (
    <a href={`/posts/${id}`} onMouseEnter={prefetch} onFocus={prefetch}>
      پست {id}
    </a>
  )
}

نکته — Structural Sharing

TanStack Query به‌صورت پیش‌فرض، پاسخ جدید را با قبلی مقایسهٔ عمیق می‌کند و مرجعِ بخش‌های بدون تغییر را حفظ می‌کند. نتیجه: useMemoهای شما کمتر می‌سوزند و React کمتر رندر می‌گیرد. خاموشش نکنید مگر با دلیل (structuralSharing: false).

مینی‌الگو: invalidate هدفمند در سه سطح

ثبت کامنت — چه چیزهایی باید stale شوند؟js
const addComment = useMutation({
  mutationFn: (vars) => api.addComment(vars.postId, vars.body),
  onSuccess: (comment, vars) => {
    // ۱) کامنت‌های همان پست
    qc.invalidateQueries({ queryKey: postKeys.comments(vars.postId) })
    // ۲) شمارندهٔ کامنت در جزئیات پست
    qc.invalidateQueries({ queryKey: postKeys.detail(vars.postId) })
    // ۳) «کامنت‌های اخیر من» در داشبورد — دامنهٔ متفاوت
    qc.invalidateQueries({ queryKey: ['my-activity'] })
  },
})

جمع‌بندی فصل

  • کلید سلسله‌مراتبی و serialize‌پذیر بنویسید؛ پارامترها داخل کلید، نه در State جدا.
  • Query Key Factory + queryOptions = کلید و fetch و تایپ در یک نقطه.
  • invalidate تطبیق جزئی دارد؛ با exact یا predicate هدف بگیرید.
  • prefetch برای سرعت، ensureQueryData برای لودرها، remove/clear برای خروج کاربر.
  • Structural sharing مرجع پایدار می‌دهد؛ همان چیزی که Zustand هم دوست دارد.
تمرین فصل ۱۱

برای دامنهٔ users یک Query Key Factory کامل بنویسید (all/lists/list/detail/posts). بعد صفحهٔ «پروفایل کاربر» بسازید که با hover روی لینکِ کاربر، جزئیاتش را prefetch می‌کند. در logout اپ، کل کش را پاک کنید و با DevTools مطمئن شوید چیزی باقی نمانده.
